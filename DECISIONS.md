# Decisions

Autonomous build log. Each entry: date · decision · reason. Newest at the bottom of each milestone.

## M0 — Setup

- **2026-09-29 · pnpm workspace with a single Next.js app (`apps/web`), no Turborepo.** One JS package does not need a task runner; root scripts delegate with `pnpm --filter web`.
- **2026-09-29 · Next.js 16 (App Router) with `proxy.ts` instead of `middleware.ts`.** Next 16 renamed middleware to proxy; only next-intl routing runs there.
- **2026-09-29 · next-intl with `localePrefix: "as-needed"`: Bangla at `/`, English at `/en`, no browser-language detection.** Bangla must be the default for everyone (many phones are set to English); URLs stay short for WhatsApp sharing, and pages can be statically rendered.
- **2026-09-29 · `/messages/{bn,en}.json` at the repo root** (per the agent prompt). `next.config.ts` sets `outputFileTracingRoot`/`turbopack.root` to the repo root so the app can import them. On Vercel keep "Include files outside the root directory" enabled (default).
- **2026-09-29 · Self-hosted Noto Sans Bengali via `@fontsource`** instead of `next/font/google`. Works offline in the PWA, no build-time Google Fonts fetch; the unicode-range split means Latin pages don't download Bengali glyphs.
- **2026-09-29 · Hand-written service worker (`public/sw.js`) instead of next-pwa/Serwist.** It is ~200 lines, has no build step, and we need custom Background Sync + push logic anyway.
- **2026-09-29 · The web app never holds a service-role key.** Browser uses the anon key + RLS; privileged work runs in Supabase Edge Functions or workers. Staff invites are rows in `staff_invites` that a trigger applies on first sign-in, so no admin API is needed from Vercel.
- **2026-09-29 · Playwright runs one project: Pixel 5 profile at 360×740.** The definition of done targets low-end Android Chrome. `PW_CHROMIUM_PATH` lets sandboxes use a preinstalled Chromium.

## M1 — Schema + seed

- **2026-09-29 · Ward ids are deterministic: DNCC ward n → n, DSCC ward n → 100 + n.** Workers, seeds and GeoJSON uploads can refer to wards without lookups.
- **2026-09-29 · `wards.geom` is nullable.** Ward rows (names, numbers) exist from day one; boundaries are loaded later. Reports outside every known polygon get `ward_id = null` and are backfilled when a boundary is uploaded (`upsert_wards_geojson`).
- **2026-10-01 · Ward boundaries come from DGHS (Government of Bangladesh), both city corporations from one source.** `supabase/seed/fetch_wards_dghs.py` reads the DNCC (54) and DSCC (75) ward layers behind the DGHS EPI GIS dashboard (dashboard.dghs.gov.bd); all 129 wards are present, valid, and DNCC and DSCC do not overlap. OSM (`fetch_wards.py`) had no usable ward relations for Dhaka. DNCC's own layer (github.com/dnccinnovationlab/dengue-dashboard, `DNCC_Ward_Boundary_poly_urp_f`) was compared: same numbering, median per-ward IoU 0.74, with real line differences around Mirpur (wards 6, 11–13, 47, 50); mixed with DGHS DSCC it overlaps DSCC by 2.4 km², so it was not used. Replace any ward with official DNCC/DSCC files via `/staff/admin` when available. The source files state no licence; they are published by government bodies for public health use.
- **2026-09-29 · Citizens do not insert into `reports` directly; the `submit-report` Edge Function does (service role).** The function must strip EXIF and store the photo anyway, and a direct PostgREST insert would allow forged `photo_path`s. Anonymous users therefore "insert reports" only through that function. Rate limits (10/hour, 30/day per `device_hash`) are enforced twice: in the function (friendly 429) and in a `BEFORE INSERT` trigger (errcode `P0429`) so no path can bypass them.
- **2026-09-29 · Citizens use Supabase anonymous sign-in.** Gives every reporter a stable `reporter_id` (to track their own reports and receive push) without collecting identity. Phone OTP can later be linked to the same user.
- **2026-09-29 · `device_hash` = SHA-256(random per-install id + server salt), computed server-side.** The raw id never reaches the database; the salt (`DEVICE_HASH_SALT`) stops cross-referencing.
- **2026-09-29 · Duplicate merge is serialised with a transaction-scoped advisory lock.** Two simultaneous reports of the same spot would otherwise both create a site. At the target load (50 reports/minute) a single lock is negligible.
- **2026-09-29 · Site state machine enforced in a `BEFORE UPDATE` trigger with a role × transition matrix (`site_transition_allowed`).** RLS decides *which rows* a role may update; the trigger decides *which transitions*, and enforces "cleared needs an after photo taken within 50 m" (`after_photo_geom`) and "not_found needs a reason" for everyone, including the service role.
- **2026-09-29 · Moderation and merge are `security definer` RPCs (`moderate_report`, `merge_sites`) with explicit role checks.** They touch reports, sites and `ai_labels` atomically; statements they run count as "system" in the state-machine trigger. Every moderator decision writes `ai_labels.moderator_label` (the site type for approvals, `not_relevant` for rejections) as training data for P3.
- **2026-09-29 · `site_events` is append-only via trigger (no UPDATE/DELETE, even for the owner) except stamping `notified_at`.** The notifier needs to mark events as pushed; all audit columns are immutable.
- **2026-09-29 · Public data only through owner-rights views (`public_sites`, `public_wards`, `public_ward_scorecard`, `public_case_counts`, `public_ward_risk`) and two GeoJSON RPCs.** Tables stay closed to `anon`. `public_sites` snaps points with `ST_SnapToGrid(geom, 0.0005)` (~55 m N–S, ~51 m E–W at Dhaka's latitude), hides rejected/merged sites and shows a thumbnail only after blurring succeeded.
- **2026-09-29 · Scorecard % cleared within 72 h excludes open sites younger than 72 h from the denominator.** Otherwise a ward that received many reports yesterday would look worse than it is.
- **2026-09-29 · Researchers: an anonymised report-level view (`research_reports`) gated by role, not a separate API-key system.** Researchers sign in with email like other staff and use their session token with the REST API or the export page. Keys are salted hashes of ids; no reporter, device, note or photo columns.
- **2026-09-29 · Case counts `area` uses codes (`DNCC`, `DSCC`, `DHAKA_DIV`, …, `BANGLADESH`).** Stable keys across Bangla/English bulletins; manual entries (`entered_by` not null) are never overwritten by the scraper.
- **2026-09-29 · Scheduled jobs use pg_cron + pg_net calling Edge Functions with Vault secrets (`project_url`, `service_role_key`).** No secrets in migrations; jobs are no-ops until the operator creates the secrets.
- **2026-09-29 · RLS tests use pgTAP via `supabase test db`.** Runs against the real migrations in CI.
- **2026-09-29 · Admin ward upload goes through the same `upsert_wards_geojson` RPC as the seed script, with client-side validation first (`src/lib/geojson.ts`).** One code path for OSM and official boundaries; ward admins can only load their own city corporation.
- **2026-09-29 · `supabase/seed/dev_demo.sql` draws a synthetic ward grid (`geom_source = 'synthetic-demo'`) and fake reports for local dev and CI e2e only.** Lets the map, scorecards and queues be exercised without real boundaries; clearly labelled and never part of `seed.sql`.

## M2 — Report flow

- **2026-09-29 · The browser re-encodes every photo to ≤1600 px JPEG via canvas before queueing.** Canvas output carries no EXIF, so GPS/camera metadata never leaves the phone, uploads are ~200–400 KB on 3G, and orientation is baked in. The server strips EXIF again (`_shared/jpeg.ts`, a byte-level APPn/COM remover) because clients can't be trusted.
- **2026-09-29 · Every report is written to IndexedDB *before* the upload is attempted.** A dropped connection mid-upload can't lose a report; the queue is flushed on submit, on the `online` event, on app start, and by the service worker's Background Sync (Chromium) with the anon key if no tab is open.
- **2026-09-29 · Report ids are generated on the device (UUID) and used as `reports.id`.** Makes retries idempotent: a resent report returns the existing row instead of creating a duplicate.
- **2026-09-29 · The done screen renders in place instead of navigating.** Navigation needs a server round-trip, which fails offline; the queued state must still show tips and sharing.
- **2026-09-29 · "Move the map, not the pin": a fixed centre pin over a draggable MapLibre map.** Easier with one thumb than dragging a small marker; starts at the GPS fix with accuracy shown.
- **2026-09-29 · JS budget: the report route's initial JS is ~164 KB gzipped (budget 200 KB), measured by an e2e test.** MapLibre (~300 KB gz) is lazy-loaded only for the location step (prefetched once a photo is chosen) and the CLIP model is lazy-loaded in a worker; both are excluded like the model. Zod is kept out of client bundles (`report/types.ts` has no runtime deps; `report/schema.ts` is test/server only), supabase-js is loaded only when uploading, and global nav links don't prefetch other routes (saves data on 3G). The 39 KB `noModule` polyfill chunk is never downloaded by modern browsers.
- **2026-09-29 · MapLibre's worker is copied to `public/maplibre/` at build (`scripts/copy-maplibre-worker.mjs`) and set with `setWorkerUrl`.** Bundlers don't follow MapLibre's dynamic worker URL.
- **2026-09-29 · Notes are scrubbed of phone numbers and emails server-side (`sanitizeNote`, Latin and Bangla digits).** The form asks people not to write them, but some will.
- **2026-09-29 · Phone OTP rule has a free fallback.** With `PHONE_OTP_ENABLED=false` (no paid SMS provider), a device's 6th+ report is accepted but its device label is downgraded from `likely` to `unclear`, so it goes to human review first.
- **2026-09-29 · Share card is drawn client-side on a canvas (1080×1080 PNG) and shared with the Web Share API (files), falling back to a download; text sharing falls back to a `wa.me` link.** No server rendering needed, works offline.

## M3 — Screening + moderation

- **2026-09-29 · On-device model: `Xenova/clip-vit-base-patch32`, 8-bit quantized, via transformers.js in a module Web Worker (WASM backend), configurable with `NEXT_PUBLIC_CLIP_MODEL_ID`.** Proven zero-shot CLIP weights with ONNX exports; transformers.js caches files in the Cache API so the download happens once. The worker is created on first idle after the report screen renders.
- **2026-09-29 · The model is only downloaded on capable devices and connections**: skipped when `deviceMemory < 3 GB`, `hardwareConcurrency < 4`, Data Saver is on, or `effectiveType` is 2g/3g. The model is tens of MB; mobile data is expensive in Bangladesh. If it is not ready 20 s after a photo is chosen, the report goes out as `pending` (the download continues and is cached for next time). Maintainers should evaluate MobileCLIP (`Xenova/mobileclip_s0`) as a smaller default once it can be tested on real Dhaka photos.
- **2026-09-29 · Label mapping: score = softmax probability mass on the 8 positive prompts (of 14); ≥0.6 → likely, ≤0.25 → not_relevant, else unclear.** A single "P(breeding site)" score has the same meaning for the device, paid API and P3 detector, so moderators can compare them. Thresholds are deliberately lenient; `not_relevant` only triggers a gentle "are you sure?".
- **2026-09-29 · Moderation queue is a security-invoker view (`moderation_queue`) over reports whose site is still `new` and that no human has decided.** Order: pending → unclear → not_relevant (likely spam) → likely, then oldest first. RLS still applies, so ward admins see only their corporation.
- **2026-09-29 · Moderator actions are RPCs (approve / reject / relabel / merge) with shortcuts A, R, 1–8, M, J/K.** Every decision writes `ai_labels.moderator_label` (the approved site type, or `not_relevant`), which `/workers/detector` exports as training data.
- **2026-09-29 · Paid tier (`screen-report`) uses a provider interface (`_shared/vision.ts`): Anthropic via the official TypeScript SDK (npm specifier in Deno), Gemini via REST, and the self-hosted detector (`VISION_PROVIDER=model`).** Anthropic calls request constrained JSON (`output_config.format` json_schema) and every provider's output is validated with the same zod schema; invalid output → `unclear`. Default model `claude-haiku-4-5-20251001` per the brief (cheap, vision-capable).
- **2026-09-29 · The paid tier runs only if `PAID_AI_ENABLED=true`, only for `unclear`/`pending` reports not yet seen by a paid/model provider, never overwrites a human decision, and is hard-capped by an atomic per-day counter (`claim_ai_quota`, Asia/Dhaka day, `AI_DAILY_CAP`, default 100).** Cost stays bounded even if the cron and submit paths race.
- **2026-09-29 · `@anthropic-ai/sdk` pinned to `^0.128.0` in the Deno import map.** Deno's resolver refused the release published the day before (0.129.0); the pin avoids that and keeps function deploys reproducible.

## M4 — Public map

- **2026-09-29 · Public pages use plain `fetch` against PostgREST (`lib/publicApi.ts`) instead of supabase-js.** Keeps public page JS small and lets Next cache responses (`revalidate` 5–15 min) on Vercel.
- **2026-09-29 · Site clustering is MapLibre's built-in GeoJSON clustering over `public_sites_geojson` (max 5000 newest points per request).** No extra tile server; fine at pilot scale. Revisit with vector tiles (e.g. PostGIS `ST_AsMVT`) if the public map exceeds ~5000 open sites.
- **2026-09-29 · The base-map style is fetched with a 6 s timeout and falls back to a plain background style.** On flaky 3G or if OpenFreeMap is down, sites, clusters and the ward choropleth still render (cluster count labels need the base style's glyphs and are skipped in fallback).
- **2026-09-29 · Popups are built with DOM `textContent`, never HTML strings.** Site data comes from citizens; this rules out injection.
- **2026-09-29 · The risk layer is always labelled "environmental risk, not confirmed cases" (map, legend, ward page, method page), and wards without data show "No data" rather than a colour.**
- **2026-09-29 · Ward pages are rendered on demand with 5-minute revalidation (no build-time static params).** Builds don't need database access, and scorecards stay fresh.

## M5 — Inspector app

- **2026-09-29 · Staff invites are email-based: an admin adds a row to `staff_invites`; the person signs in with a one-time email code/link and a trigger applies the role and ward.** No admin API or service key is needed in the web app, and invites work for people who already used the app anonymously (the trigger also fires on email change).
- **2026-09-29 · Inspector queue = security-invoker view `inspector_queue`, sorted by the ward's latest risk level, then oldest first; sites open for more than 72 h are highlighted.** Ward admins see their whole city corporation in the same view through RLS.
- **2026-09-29 · Navigation uses an Android `geo:` URI (opens whatever maps app the inspector has) with an OpenStreetMap directions link as fallback.** No Google Maps dependency or key.
- **2026-09-29 · "Cleared" needs a fresh on-site after photo: the browser takes a GPS fix at photo time (not EXIF), shows the distance, and only enables confirm within 50 m; the DB trigger re-checks the 50 m rule against `after_photo_geom`.** Client check is for UX, server check is the guarantee. After photos go to the private `after-photos` bucket under `<site_id>/`, writable only by staff who manage that ward.
- **2026-09-29 · Web push via `notify-status` (pg_cron every 5 min) using `@negrel/webpush` (MIT, Deno-native, RFC 8291/8292) with standard base64url VAPID keys converted to JWK.** Notifies reporters on verified/assigned/cleared/not_found, in the subscriber's language; expired (410) subscriptions are deleted; each event is stamped `notified_at` so nothing is sent twice. Without VAPID keys the job just stamps events (free fallback: status is visible on "My reports").
- **2026-09-29 · Push notification strings live in `_shared/i18n.ts`, and a unit test asserts they equal `/messages/*.json`.** Edge Functions can't reliably import files outside `supabase/functions` at deploy time.

## M6 — Case data

- **2026-09-29 · `workers/cases` tries a list of sources (`CASES_SOURCE_URLS`: DGHS pages and news re-publications) and parses HTML tables, English/Bangla press-release prose and PDFs (Bangla digits and area names normalised to codes).** The DGHS bulletin format changes often; several parsers and sources make a daily miss less likely. An undated document is skipped rather than guessed.
- **2026-09-29 · The job exits non-zero when nothing parses, so Northflank marks the run failed; admins then use the manual entry form on `/staff/admin`.** Manual rows (`entered_by` set) are never overwritten by the scraper (`ON CONFLICT … WHERE entered_by IS NULL`).
- **2026-09-29 · Default source URLs are best guesses that could not be reached from the build sandbox; they must be verified on first deploy.** The parsers are tested against realistic English and Bangla fixtures.
- **2026-09-29 · Cron `0 4 * * *` UTC = 10:00 Asia/Dhaka, as specified; DGHS often publishes in the afternoon, so the 10:00 run usually upserts the previous day's bulletin (idempotent). An optional second run at `0 12 * * *` is documented.**

## M7 — Satellite risk

- **2026-09-29 · odc-stac median composites over a 60-day lookback (≤40 % cloud) from Planetary Computer: Sentinel-2 L2A (SCL cloud/shadow mask, harmonised −1000 offset for processing baseline ≥ 04.00) for NDVI, MNDWI, NDBI at 20 m; Landsat C2 L2 `lwir11` for LST (°C) with QA_PIXEL masking at 30 m.** A two-month median survives monsoon cloud cover better than single scenes.
- **2026-09-29 · Zonal means use our own rasterio `geometry_mask` code (no GPL zonal-stats packages); wards without a boundary are skipped.**
- **2026-09-29 · Score = Σ wᵢ·zᵢ / Σ|wᵢ| over z-scores across wards (clipped ±3; missing or zero-spread inputs count as 0), weights and thresholds in `weights.yaml` (`v0.1-uncalibrated`, stored in `ward_risk.method_version`).** Transparent and easy to recalibrate against DSCC/DNCC larval surveys. Four levels by fixed thresholds by default (a percentile mode exists but always paints some wards red).
- **2026-09-29 · Rainfall: one batched Open-Meteo request for all ward centroids (archive API for weeks older than ~80 days), falling back to the city centroid, then NULL.** Free, no key.
- **2026-09-29 · Weekly cron `0 21 * * 0` UTC (Monday 03:00 Asia/Dhaka); the job needs ~4 GB RAM on Northflank.**

## Photo privacy and P3 detector

- **2026-09-29 · Face/number-plate blurring runs in `workers/thumbs` (Python, every 5 min), not in an Edge Function.** Edge Functions can't run OpenCV; a small cron job can. It uses OpenCV YuNet (Apache-2.0, multi-scale) for faces and OpenCV's bundled Haar plate cascade on the full-resolution image, blurs padded boxes, then downscales to ≤480 px without metadata.
- **2026-09-29 · Thumbnails fail closed: any decode/detector error or missing model marks the report `thumb_status = 'failed'` and nothing is uploaded; the public views only ever expose thumbnails with `thumb_status = 'ok'`.** Network/storage errors leave the row pending for the next run. The Haar plate detector is a weak baseline for Bangladeshi plates; improving it (or blurring all detected vehicles) is a follow-up.
- **2026-09-29 · P3 detector (`workers/detector`): Ultralytics YOLO classification (`yolo11n-cls`) trained on moderator-labelled photos, served as `POST /screen` with the same `{label, score, site_type}` contract as the paid providers (`VISION_PROVIDER=model`).** Ultralytics is AGPL-3.0, compatible with this project, and kept out of the default install (`requirements-train.txt`). The server only fetches `image_url`s from an allow-listed host and checks a bearer token in constant time.

## M8 — Digest + export

- **2026-09-29 · Digest email is HTML sent through Resend's HTTP API (free tier) when `RESEND_API_KEY` is set; the "PDF" is the printable `/staff/digest` page (browser "Save as PDF").** Generating PDFs in an Edge Function needs a headless browser or heavy libraries; print CSS gives the same result for free. Without an email key the job still runs and logs, so there is a free fallback. `digest_log` makes the job idempotent per week and recipient.
- **2026-09-29 · Digest numbers come from one SQL function (`ward_digest`) shared by the email and the printable page; recipients are ward admins (`digest_recipients`, service role only).** One definition of "new / cleared / overdue".
- **2026-09-29 · Exports are Next.js route handlers (`/api/export/*`) that read the public views with the anon key and are CDN-cached for an hour.** No privileged code; the research export forwards the caller's own token so the `research_reports` role check decides. CSV cells are protected against spreadsheet formula injection and start with a UTF-8 BOM so Excel shows Bangla correctly.
- **2026-09-29 · Public thumbnails now also require the site to have been verified by a moderator (`public_sites`), on top of successful blurring.** Two independent checks before any citizen photo is public.
- **2026-09-29 · Security fix: role checks inside `security definer` functions must use the JWT (`auth.uid()`), not `current_user` (which is the owner there).** `upsert_wards_geojson` had used `is_end_user_context()` and would have let any signed-in user load ward boundaries; fixed in `20260929000701` with regression tests.

## M9 — Hardening

- **2026-09-29 · The public map uses a facade on phones: a server-rendered SVG preview (ward risk colours + last-28-day sites, no JS) with a tap to load the interactive MapLibre map; desktops with a mouse get the interactive map directly.** MapLibre's WebGL start-up caused ~1.7 s of main-thread blocking under Lighthouse's mobile throttling (score 61). The preview paints instantly on low-end Android over 3G, is accessible (`role="img"` with a count), and the full map is one tap away. Mobile performance went 61 → 96–99.
- **2026-09-29 · Bangla font: our own `@font-face` with `local("Noto Sans Bengali")` first, Bengali unicode-range only, `font-display: optional`, the regular weight preloaded and cached by the service worker.** Android phones ship Noto Sans Bengali, so most users never download it; `optional` removed the layout shift on the ward table (CLS 0.28 → 0). The `@fontsource` package was dropped; the two woff2 files and the OFL licence live in `public/fonts`.
- **2026-09-29 · Lighthouse in CI enforces accessibility ≥ 95 and only warns on performance < 90.** Shared CI runners give noisy performance numbers; a11y is deterministic. Reports stay on the runner (filesystem target), nothing is uploaded publicly.
- **2026-09-29 · `docs/copy-review.md` is generated from the message files (`scripts/copy-review.mjs`) with a short priority list (health helpline, risk disclaimer, privacy text, larvae wording).** Reviewers always see the current strings; a unit test keeps `bn.json` and `en.json` keys and ICU placeholders in sync.
- **2026-09-29 · Load test through the real Edge Function + trigger path at 50 and 500 reports/min (all accepted, p95 83 ms locally).** The single advisory lock around site matching is not a bottleneck at pilot scale; results and method in `docs/operations.md`.
- **2026-09-29 · Backups: Supabase daily backups (+ PITR once live), plus an independent weekly encrypted `pg_dump` of `public`+`auth` and an S3 sync of the private photo buckets; restore = migrations from git, then data-only restore with triggers disabled.** Documented step by step in `docs/operations.md`, with a quarterly restore drill.
- **2026-09-29 · No Content-Security-Policy header yet.** The on-device model loads ONNX Runtime WASM and model files from CDNs that redirect across hosts; a CSP that can't be tested end-to-end here risks silently disabling screening. Other security headers are set. Follow-up: add a CSP in report-only mode on staging and tighten.

## Volunteer game + redesign

- **2026-09-30 · Any citizen can destroy a reported spot themselves ("hunters"), without waiting for moderators or city-corporation inspectors.** The moderator and inspector flows stay exactly as they were; volunteers are an extra, faster path. A hunter claims a spot (3-hour lock, at most 3 at a time, 10 cleans a day), takes an after photo on site, and the server (`complete_cleanup`) checks the photo exists in their own storage folder and that the GPS point is within 50 m of the true (unsnapped) site location before marking it cleared. The phone only sees the ~50 m-snapped point, so the client allows 90 m and the server decides.
- **2026-09-30 · Trust after, not before: a volunteer cleanup is live immediately; moderators spot-check "Cleanup proofs" (before/after side by side, distance) and can reverse a fake one (`reject_cleanup`), which reopens the spot and revokes the points.** Moderation of every cleanup would recreate the bottleneck the game is meant to remove.
- **2026-09-30 · Points are an append-only ledger (`points_ledger`), not a counter.** Report +5 (revoked if the report is later marked not relevant), destroy +20, +10 if larvae were seen, +10 if the spot was open more than 3 days, +10 only for destroying your own report. Leaderboard, weekly board, levels (Rookie → Mohalla Hero) and badges are all derived from the ledger, so reversals are exact and rules can change without migrations of totals. Rules live in `game_rules()` and are mirrored in `lib/game/rules.ts`.
- **2026-09-30 · Public identity is a self-chosen hunter name and an optional avatar only.** The leaderboard view exposes handles, avatars and totals, never user ids, emails or phone numbers; reporter identity is still never shown on a spot. Hunters stay anonymous Supabase users; linking an email (`updateUser` + `email_change` OTP) only lets them keep their card on a new phone.
- **2026-09-30 · Spot photos are public once blurred, without waiting for a moderator.** Blurring still fails closed (no thumbnail if faces/plates can't be processed). This reverses the M8 "verified first" rule, because a public to-do list without photos is useless to volunteers. Volunteer after photos go through the same `workers/thumbs` blurring before appearing publicly.
- **2026-09-30 · Maximum compression, since storage and bandwidth are the main running cost.** Client photos: ≤1024 px, JPEG quality stepped down until ≤120 KB (typically 60–110 KB); avatars 256 px ≤25 KB; public thumbnails 320 px, quality 50, progressive, 4:2:0. Server limits: `submit-report` 2 MB, `cleanup-photos` bucket 512 KB, `avatars` 128 KB.
- **2026-09-30 · The map shades wards by citizen reports in the last 28 days by default, with a one-tap switch to environmental risk.** Report counts are what people act on; the risk layer keeps its "not confirmed cases" disclaimer and is only shown when selected.
- **2026-09-30 · Visual identity drawn from the Aedes mosquito itself: ink-navy body with white leg bands (the striped "Aedes band" used for progress bars, podiums and the header edge), blood red for reporting/danger, neem green for destroyed spots, marigold for XP and rewards.** Display font Baloo Da 2 (OFL, self-hosted, one 800 weight) for a friendly, game-like feel in both Bangla and Latin; body text stays Noto Sans Bengali. All status colours keep ≥ 4.5:1 contrast with white text. Lighthouse after the redesign: performance 92–97, accessibility 100 on `/`, `/sites`, `/leaderboard`, `/me`, `/map`.

## Design + game review and security hardening

- **2026-10-01 · Reviewed with the game-ui-ux, game-feel, ui-ux-pro-max and anti-slop skills (vendored in `.claude/skills/`) and against similar products.** References: DengueChat (Nicaragua/Brazil; brigades and "green houses" kept free of breeding sites, 90 % vector reduction in the pilot), Mosquito Alert (points by report type, levels, global leaderboard, expert validation), Litterati (photo proof, groups and challenges) and Duolingo (weekly leagues, streaks). Adopted: before/after reveal, XP count-up, filling level bar, haptic buzz and one-shot confetti on a cleanup (all off with reduced motion); a "next spot near here" suggestion; a **weekly** streak (not daily, which would push fake activity); a ward-vs-ward weekly board (DengueChat's brigades, Litterati's groups). Fixed: header overflow with the XP chip, two primary buttons at once in the cleanup flow, emoji used as control icons (one SVG line-icon family now; emoji remain only as site-type illustrations), pointer cursor on buttons.
- **2026-10-01 · Not adopted (yet):** demotion leagues (pressure without benefit for volunteers); daily streaks; prizes. Proposed next: a "re-check" quest one week after a cleanup (Aedes eggs survive drying, containers refill; DengueChat's two-month "green house" rule), and school or club teams.
- **2026-10-01 · Volunteer abuse controls follow from the security review (`docs/security-review-2026-10-01.md`):** trust tiers (limits grow with confirmed XP: 1/3, 2/6, 3/10 claims/cleans), 48 h "confirming" window for clean points with moderator approve/reverse, one fresh photo per claim, distance checked against the public point (80 m) so the RPC never reveals an exact location, report points on moderator verification published in a daily batch.
